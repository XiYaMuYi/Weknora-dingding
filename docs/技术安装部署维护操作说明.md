## 3. 部署前准备

### 3.1 基础环境

必需：

- Docker
- Docker Compose
- Git

建议：

- 基础验证至少 4 核 CPU、8 GB 内存。
- 生产环境根据文档量、并发解析量、模型部署方式扩容。
- 生产环境部署在内网或受控网络，不建议直接暴露公网。

### 3.2 默认访问地址

| 服务 | 默认地址 |
|---|---|
| Web UI | `http://localhost` |
| 后端 API | `http://localhost:8080` |
| PostgreSQL | `localhost:5432` |
| Redis | `localhost:6379` |
| MinIO Console | `http://localhost:9001` |
| Neo4j Browser | `http://localhost:7474` |
| Langfuse | `http://localhost:3000` |

生产环境请按实际域名、HTTPS、反向代理和防火墙策略调整。

### 3.3 已批准的生产部署基线

单机内网 Compose 的生产变量、并发、上线、排障、备份和回滚操作见
[生产环境配置说明](./生产环境配置说明.md)。本文中的默认
`docker compose up -d` 仅用于功能启动说明，不是本项目批准的生产配置；生产环境必须
使用该手册中的 `make production-*` 命令和未跟踪的
`deploy/production/.env.production`。

## 4. 安装部署

### 4.1 获取代码

```bash
git clone https://gitlab.gongzhugou.vip/...(还在本地调试，暂未push)
cd WeKnora
```

如果是企业内部维护分支，请使用内部仓库地址和指定分支。

### 4.2 创建配置文件

```bash
cp .env.example .env
```

重点检查：

| 配置 | 说明 |
|---|---|
| `JWT_SECRET` | 生产环境必须改成强随机值 |
| `SYSTEM_AES_KEY` | 用于加密数据源、模型、MCP 等敏感凭证，生产环境必须妥善保管 |
| 模型相关变量 | LLM、Embedding、Rerank、多模态、ASR 等 |
| 存储相关变量 | Local / MinIO / COS / TOS |
| `WEKNORA_TENANT_ENABLE_RBAC` | 是否启用租户 RBAC，默认开启 |
| `WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL` | 首次启动后提升系统管理员 |
| `DISABLE_REGISTRATION` | 生产环境建议结合邀请制使用 |
| `OIDC_AUTH_ENABLE` | 如需企业单点登录则开启 |

### 4.3 启动核心服务

```bash
docker compose up -d
```

启动后访问：

```text
http://localhost
```

### 4.4 启动可选组件

| Profile | 说明 | 命令 |
|---|---|---|
| `full` | 尽量启动全功能依赖 | `docker compose --profile full up -d` |
| `neo4j` | 知识图谱 | `docker compose --profile neo4j up -d` |
| `minio` | MinIO 对象存储 | `docker compose --profile minio up -d` |
| `langfuse` | 链路追踪 | `docker compose --profile langfuse up -d` |
| `doris` | Doris 可选能力 | `docker compose --profile doris up -d` |

### 4.5 停止和重启

```bash
docker compose down
docker compose restart app
docker compose restart docreader
```

## 5. 首次初始化账号

### 5.1 注册第一个用户

首次访问 Web UI 后，按页面提示注册账号。默认模式下，用户注册后会自动创建自己的工作区，并成为该工作区 `Owner`。

生产建议：

- 首个账号使用企业管理员邮箱。
- 完成初始化后可开启邀请制，避免任意注册。

### 5.2 设置系统管理员

系统管理员是平台级管理员，独立于某个工作区的 `Owner/Admin/Contributor/Viewer`。

推荐方式：

1. 先在 Web UI 注册目标管理员账号。
2. 在 `.env` 中设置：

```bash
WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL=admin@example.com
```

3. 重启 `app` 服务：

```bash
docker compose restart app
```

说明：

- 该配置只会提升，不会撤销。
- 用户必须已经注册过。
- 后续系统管理员的新增、撤销建议在系统管理页面操作。

### 5.3 账号与角色层级

| 层级 | 角色 | 管理范围 |
|---|---|---|
| 平台级 | SystemAdmin | 系统管理员列表、平台级系统设置、平台审计、默认配额 |
| 工作区级 | Owner | 当前工作区最高权限，成员管理、API Key、删除工作区 |
| 工作区级 | Admin | 当前工作区资源和集成管理 |
| 工作区级 | Contributor | 创建和维护自己创建的知识库/智能体 |
| 工作区级 | Viewer | 阅读、搜索、问答 |
| API 调用 | API Key | 所属工作区内按 Admin 处理，删除工作区仍需 Owner |

## 6. 权限与安全配置

### 6.1 RBAC

默认启用：

```bash
WEKNORA_TENANT_ENABLE_RBAC=true
```

临时观察模式：

```bash
WEKNORA_TENANT_ENABLE_RBAC=false
```

观察模式会放行请求但记录角色不足日志，仅用于升级灰度，不建议长期使用。

### 6.2 注册模式

生产环境建议关闭公开注册，改为邀请制：

```bash
DISABLE_REGISTRATION=true
```

### 6.3 OIDC 单点登录

如需企业统一身份认证，可配置：

```bash
OIDC_AUTH_ENABLE=true
OIDC_AUTH_CLIENT_ID=...
OIDC_AUTH_CLIENT_SECRET=...
OIDC_AUTH_ISSUER_URL=...
```

详见：[OIDC认证调用流程](./OIDC认证调用流程.md)。

### 6.4 密钥管理

必须妥善保管：

- `.env`
- `SYSTEM_AES_KEY`
- `JWT_SECRET`
- 数据库密码
- 对象存储密钥
- 模型 API Key
- 第三方数据源凭证
- MCP 和 IM 机器人凭证

`SYSTEM_AES_KEY` 丢失后，数据库里已加密的模型、数据源、MCP 等凭证可能无法解密。

## 7. 模型、存储和检索配置

### 7.1 模型配置

常见模型类型：

| 类型 | 用途 |
|---|---|
| LLM / Chat Model | 问答、Agent 推理、Wiki 生成 |
| Embedding Model | 文档向量化，必须配置 |
| Rerank Model | 重排序，提升检索质量 |
| Multimodal / VLM | 图片、扫描件、图表理解 |
| ASR | 音频识别 |

运维可通过 `.env` 初始变量、Web UI 设置页、系统管理员内置模型配置进行管理。

### 7.2 对象存储

可使用 Local、MinIO、COS、TOS。如果启用图片、多模态或较大文件管理，建议使用对象存储，并确认公网/内网访问地址正确。

### 7.3 向量数据库

外部向量库配置、测试和切换通常需要 `Admin+` 权限。变更前建议先备份并在测试环境验证检索效果。

## 8. 日常维护

### 8.1 查看服务状态

```bash
docker compose ps
```

### 8.2 查看日志

```bash
docker compose logs -f app
docker compose logs -f docreader
docker compose logs -f postgres
docker compose logs -f redis
```

### 8.3 健康检查

```bash
curl http://localhost:8080/health
```

正常返回：

```json
{"status":"ok"}
```

### 8.4 异步任务排查顺序

常见异步任务包括文档解析、数据源同步、知识库复制、文档重新解析、Ollama 模型下载。

排查顺序：

1. 确认生产环境只有一个 `app` 容器。
2. 确认有效 Asynq 并发：环境变量为 `2`，且数据库 `asynq.concurrency` 为 `2` 或为空。
3. 检查 `processing` 文档的最长年龄，记录文档 ID 和开始时间。
4. 检查 Redis 队列状态和积压。
5. 检查 `docreader` 日志和健康状态。
6. 检查 Ollama 的可用性、延迟、CPU 和内存。
7. 收集完证据后才决定通过应用任务取消路径取消，或在状态终止后对同一文档执行一次重试。

不要以刷新页面、重启容器、手工删除 Redis 键或并发重新解析替代上述顺序。钉钉附件权限
失败属于跳过项；已完成文档恢复后先验证检索，不重新解析。

## 9. 备份与恢复

### 9.1 需要备份的内容

| 内容 | 说明 |
|---|---|
| PostgreSQL 数据库 | 用户、租户、权限、知识库元数据、凭证密文等 |
| 对象存储数据 | 上传文件、图片、多模态资源 |
| `.env` | 系统密钥和服务连接信息 |
| 外部向量库数据 | 如果使用外部向量库 |
| Neo4j 数据 | 如果启用知识图谱 |

PostgreSQL（含内置向量索引）或外部向量索引数据必须与 `data-files`/对象存储文件同批
备份；不同批次的数据库和文件不能作为可恢复生产备份。

### 9.2 PostgreSQL 备份示例

容器名和数据库名以实际环境为准：

```bash
docker compose exec postgres pg_dump -U postgres weknora > backup-weknora.sql
```

### 9.3 PostgreSQL 恢复示例

```bash
cat backup-weknora.sql | docker compose exec -T postgres psql -U postgres weknora
```

### 9.4 对象存储备份

- Local：备份本地文件目录。
- MinIO：备份 bucket 数据，或使用 `mc mirror`。
- 云对象存储：按云厂商快照、复制或生命周期策略。

### 9.5 生产恢复验证

按 [生产环境配置说明](./生产环境配置说明.md) 恢复 PostgreSQL、向量索引和 `data-files` 的
同批备份后，选择已完成文档验证检索和问答。恢复验证不重新解析或重新切片已完成文档。

## 10. 升级维护

### 10.1 队列排空与升级窗口

生产升级按以下八步执行：

1. 执行 `make production-preflight`，确认单 App 与有效并发。
2. 执行 `make production-backup dir=/absolute/backup/path` 并校验备份。
3. 记录当前镜像 tag、Git commit、配置 hash、数据库并发设置和队列深度。
4. 停止新的手工重新解析与定时数据源同步。
5. 等待队列排空；必要时仅通过应用任务取消路径终止任务。
6. 执行 `make production-deploy` 部署已批准的镜像和配置。
7. 执行 `make production-status`，验证一份小文档和两份大的钉钉表。
8. 验收通过后恢复定时同步；回滚优先恢复上一镜像 tag 和生产配置。

禁止在升级窗口中删除 Redis 键、volume 或已完成文档索引。

### 10.2 升级前

1. 阅读 `CHANGELOG.md`。
2. 备份数据库、对象存储和 `.env`。
3. 记录当前镜像版本和 Git commit。
4. 在测试环境先验证文档解析、问答、权限、数据源同步。

### 10.3 升级

```bash
git pull
docker compose pull
docker compose up -d
```

如果使用内部镜像仓库，请按内部镜像发布流程替换。

### 10.4 升级后验证

- 登录是否正常。
- 工作区切换是否正常。
- Owner/Admin/Contributor/Viewer 权限是否符合预期。
- 上传文档是否能解析完成。
- 知识库检索和问答是否正常。
- Agent 工具、MCP、数据源、IM 渠道是否正常。
- 系统管理员页面是否可用。

## 11. 常见故障

| 现象 | 排查方向 |
|---|---|
| 页面能打开但上传失败 | Embedding、DocReader、对象存储、`app` 日志 |
| 问答无结果 | 文档解析状态、索引状态、Embedding 维度、检索策略 |
| 权限不足 | 当前工作区角色、资源创建者、共享空间、RBAC 开关、审计日志 |
| 数据源同步失败 | 第三方凭证、权限、操作人权限、同步日志 |
| 系统管理员入口不可用 | 用户是否已注册、bootstrap 邮箱是否配置、`app` 是否重启 |

## 12. 运维检查清单

每日/每周：

- 检查 `docker compose ps` 是否健康。
- 检查 `app`、`docreader`、`postgres`、`redis` 日志。
- 检查磁盘空间、对象存储容量。
- 检查解析队列是否堆积。
- 检查模型服务可用性和调用额度。
- 确认 App 容器数为 1。
- 确认 `asynq.concurrency` 为 `2` 或为空。
- 检查 Ollama 延迟与 CPU。
- 检查最长 `processing` 文档年龄。
- 检查最近一次备份的校验结果。
- 检查失败的数据源同步日志。

每月/版本发布前：

- 做一次备份恢复演练。
- 检查系统管理员和工作区 Owner 是否仍有效。
- 清理不用的模型、MCP、IM、数据源凭证。
- 审查公开注册、邀请链接、嵌入渠道和跨租户共享。
- 更新安全补丁和镜像版本。
