# 钉钉知识库和钉盘同步参数获取教程（给企业管理员）

> 适用对象：钉钉企业管理员、钉钉开放平台应用管理员。  
> 使用场景：为 WeKnora 配置钉钉「知识库」或「钉盘/云盘」同步。  
> 重要说明：AppSecret / Client Secret 属于密钥，请只通过公司认可的安全渠道交付，不要发到群聊、截图或普通工单里。

---

## 1. 管理员需要提供什么

请按下表收集并交付给项目配置人：

| 参数 | 必填 | 在钉钉后台可能显示为 | 用途 | 备注 |
|---|---:|---|---|---|
| AppKey | 是 | Client ID、AppKey | 获取钉钉接口访问令牌 | 新版后台可能显示为「Client ID（原 AppKey）」 |
| AppSecret | 是 | Client Secret、AppSecret | 获取钉钉接口访问令牌 | 新版后台可能显示为「Client Secret（原 AppSecret）」 |
| 操作人 UnionID | 是 | UnionID、unionId | 代表哪个钉钉成员去读取钉盘/知识库 | 必须是能访问目标内容的成员，不是 CorpId，也不是手机号 |
| 同步类型 | 是 | 云盘 / 知识库 | 告诉系统同步钉盘还是知识库 | 两类资源的 API 和 ID 不通用 |
| 钉盘 SpaceID | 钉盘同步时需要 | spaceId | 手动指定钉盘空间 | 优先让系统列表选择；列表不可用时再手动提供 |
| 知识库 WorkspaceID | 知识库同步时需要 | workspaceId | 手动指定知识库 | 优先让系统列表选择；列表不可用时再手动提供 |
| CorpID | 通常不需要 | 企业 ID、CorpId | 历史配置或排查时备用 | 当前 WeKnora 钉钉同步主要需要 UnionID |

交付格式建议：

```text
同步类型：知识库 / 钉盘
AppKey / Client ID：
AppSecret / Client Secret：（请通过密钥渠道发送）
操作人 UnionID：
知识库 WorkspaceID：（如需要手动指定）
钉盘 SpaceID：（如需要手动指定）
CorpID：（如管理员后台可见，可一并提供，非必填）
已开通权限：
应用可见范围：
操作人是否能访问目标知识库/钉盘：是 / 否
```

## 2. 创建或确认企业内部应用

1. 打开钉钉开放平台：[https://open-dev.dingtalk.com/](https://open-dev.dingtalk.com/)
2. 使用企业管理员或具备开放平台管理权限的账号登录。
3. 进入目标企业。
4. 进入「应用开发」。
5. 如果已有专门用于同步的企业内部应用，直接打开该应用。
6. 如果没有，创建一个「企业内部应用」。

建议应用命名为类似：

```text
WeKnora 文档同步
```

## 3. 获取 AppKey 和 AppSecret

1. 在「应用开发」中打开目标企业内部应用。
2. 进入「凭证与基础信息」或「基础信息」页面。
3. 找到以下字段并复制：
   - `Client ID（原 AppKey）` 或 `AppKey`
   - `Client Secret（原 AppSecret）` 或 `AppSecret`
4. 如果 Secret 默认隐藏，点击显示、复制或重置按钮前，请确认公司密钥管理要求。

注意：

- AppKey 可以明文发给配置人。
- AppSecret 必须按密钥处理。
- 不要把含 AppSecret 的后台截图发到群里。

## 4. 获取操作人 UnionID

WeKnora 同步钉盘和知识库时，需要一个「操作人 UnionID」。这个成员相当于同步账号：系统会以这个成员的权限读取他能访问的钉钉内容。

操作建议：

1. 优先使用一个专门的钉钉成员作为同步账号，例如「WeKnora同步账号」。
2. 确认该成员能打开目标钉盘空间或目标知识库。
3. 在通讯录、成员详情、导出成员列表或管理员后台中查找该成员的 `UnionID`。
4. 如果后台只显示 `UserID` 而不显示 `UnionID`，请联系钉钉管理员或开放平台管理员确认如何导出/查询成员标识；不要用手机号、姓名、UserID 直接代替 UnionID，除非配置人确认当前版本支持。

截图占位：

```text

[截图 6：导出成员列表后的字段示例，标出 UnionID；正式截图请打码个人信息]
```

核对清单：

- 这个成员能访问要同步的知识库或钉盘。
- 这个成员未离职、未禁用。
- 这个成员在应用可见范围内。

## 5. 开通接口权限

进入目标应用后，打开「权限管理」或「接口权限」页面，按同步类型开通权限。

### 5.1 钉盘/云盘同步

建议搜索并开通以下权限：

| 权限标识 | 用途 |
|---|---|
| `Drive.Space.Read` | 读取企业钉盘空间列表 |
| `Storage.File.Read` | 读取钉盘空间里的文件/目录 |

### 5.2 知识库同步

建议搜索并开通以下权限：

| 权限标识 | 用途 |
|---|---|
| `Wiki.Workspace.Read` | 获取操作人可访问的知识库列表 |
| `Wiki.Node.Read` | 获取知识库下的目录和文档节点 |
| `Storage.File.Read` | 读取钉钉在线文档正文或文件内容 |

如果调用接口时报错里出现 `requiredScopes`，请把报错中的权限标识补充开通。

- 如果应用没有发布，普通成员可能无法正常授权或调用。

## 7. 获取知识库 WorkspaceID（仅知识库同步需要）

优先方式：让 WeKnora 使用 AppKey、AppSecret、UnionID 自动列出可访问知识库，然后在界面里选择。

只有列表暂时不可用时，才需要管理员手动提供 `workspaceId`：

1. 确认操作人能在钉钉里打开目标知识库。
2. 在钉钉开放平台接口调试、后台工具或内部脚本里调用「查询用户有权限的知识库列表」。
3. 找到目标知识库对应的 `workspaceId`。
4. 交付时写成：

```text
知识库 WorkspaceID：xxxxxxxx
```

或：

```text
wiki:xxxxxxxx
```

不要填写浏览器地址，也不要把钉盘的 spaceId 填到知识库里。

## 8. 获取钉盘 SpaceID（仅钉盘同步需要）

优先方式：让 WeKnora 使用 AppKey、AppSecret、UnionID 自动列出可访问钉盘空间，然后在界面里选择。

只有列表暂时不可用时，才需要管理员手动提供 `spaceId`：

1. 确认操作人能在钉钉里打开目标钉盘空间。
2. 在钉钉开放平台接口调试、后台工具或内部脚本里调用钉盘空间列表接口。
3. 找到目标空间对应的 `spaceId`。
4. 交付时写成：

```text
钉盘 SpaceID：xxxxxxxx
```

或：

```text
space:xxxxxxxx
```

不要填写浏览器地址，也不要把知识库的 workspaceId 填到钉盘里。

## 9. 最终交付前自检

请管理员在交付前确认：

- 已提供 AppKey / Client ID。
- 已通过安全渠道提供 AppSecret / Client Secret。
- 已提供操作人 UnionID。
- 已说明同步类型是「知识库」还是「钉盘」。
- 已开通对应的 Drive / Storage / Wiki 权限。
- 操作人在应用可见范围内。
- 操作人能在钉钉客户端打开目标知识库或钉盘。
- 如果手动提供 ID，知识库使用 `workspaceId`，钉盘使用 `spaceId`。

## 10. 常见问题

### 10.1 AppKey 在后台找不到，只看到 Client ID

可以使用 Client ID。钉钉新版后台可能把 AppKey 显示为 `Client ID（原 AppKey）`。

### 10.2 AppSecret 在后台找不到，只看到 Client Secret

可以使用 Client Secret。钉钉新版后台可能把 AppSecret 显示为 `Client Secret（原 AppSecret）`。

### 10.3 UnionID、UserID、CorpID 是同一个东西吗

不是。

- UnionID：当前同步需要的操作人标识。
- UserID：企业通讯录里的成员 ID，部分产品或接口会用，但当前同步配置不要直接拿它替代 UnionID。
- CorpID：企业标识，当前 WeKnora 钉钉同步通常不是必填项。

### 10.4 为什么能拿到 AppKey 和 Secret，还是同步不到知识库

常见原因：

- 没有开通 Wiki 相关接口权限。
- 操作人不能访问目标知识库。
- 应用可见范围没有包含操作人。
- 手动 ID 填错，把钉盘 spaceId 和知识库 workspaceId 混用了。

### 10.5 为什么能同步钉盘，不能同步知识库

钉盘和知识库是两套不同 API。钉盘通常使用 `spaceId`，知识库使用 `workspaceId`。已开通 `Drive.Space.Read` / `Storage.File.Read` 不代表已经开通知识库权限。
