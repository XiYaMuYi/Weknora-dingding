# 钉钉知识库和钉盘同步参数获取教程（给企业管理员）

> 适用对象：钉钉企业管理员、钉钉开放平台应用管理员。  
> 使用场景：为 WeKnora 配置钉钉「知识库」或「钉盘/云盘」同步。  
> 重要说明：AppSecret / Client Secret 属于密钥，请只通过公司认可的安全渠道交付，不要发到群聊、截图或普通工单里。
> 填写表：请配合 [钉钉同步参数填写表（给企业管理员）](./钉钉同步参数填写表-给企业管理员.md) 使用；教程负责说明怎么找，填写表负责收集最终结果。

## 1. 管理员需要提供什么

请按下表收集并交付给项目配置人：

| 参数 | 必填 | 在钉钉后台可能显示为 | 用途 | 备注 |
|---|---:|---|---|---|
| AppKey | 是 | Client ID、AppKey | 获取钉钉接口访问令牌 | 新版后台可能显示为「Client ID（原 AppKey）」 |
| AppSecret | 是 | Client Secret、AppSecret | 获取钉钉接口访问令牌 | 新版后台可能显示为「Client Secret（原 AppSecret）」 |
| 操作人 UnionID | 是 | UnionID、unionId | 代表哪个钉钉成员去读取钉盘/知识库 | 通常不在应用页面展示，建议按第 4 节用接口查；不会调接口时提供手机号/userId/姓名让我们查 |
| 同步类型 | 是 | 云盘 / 知识库 | 告诉系统同步钉盘还是知识库 | 两类资源的 API 和 ID 不通用 |
| 机器人能力 | 需要聊天时必填 | 机器人、ChatBot、Stream 模式、HTTP 模式 | 让同一个钉钉应用变成可对话机器人 | 需要在应用能力中添加「机器人」并发布 |
| Card Template ID | 使用 AI 卡片时需要 | 卡片模板 ID、cardTemplateId | 支持流式 AI 卡片回复 | 不用 AI 卡片时可不提供，系统会退回普通消息 |
| 钉盘 SpaceID | 钉盘同步时需要 | spaceId | 手动指定钉盘空间 | 通常要通过接口查，见第 8 节；不会调接口时提供钉盘名称/链接/截图让我们查 |
| 知识库 WorkspaceID | 知识库同步时需要 | workspaceId | 手动指定知识库 | 通常要通过接口查，见第 7 节；不会调接口时提供知识库名称/链接/截图让我们查 |
| CorpID | 通常不需要 | 企业 ID、CorpId | 历史配置或排查时备用 | 当前 WeKnora 钉钉同步主要需要 UnionID |

交付格式建议：

```text
同步类型：知识库 / 钉盘
AppKey / Client ID：
AppSecret / Client Secret：（请通过密钥渠道发送）
操作人 UnionID：
知识库 WorkspaceID：（如需要手动指定）
钉盘 SpaceID：（如需要手动指定）
CorpID：（如管理员后台可见，可一并提供，非必填）
是否添加机器人能力：是 / 否
机器人消息接收模式：Stream / HTTP
Card Template ID：（如启用 AI 卡片）
已开通权限：
应用可见范围：
操作人是否能访问目标知识库/钉盘：是 / 否
```

如果管理员不方便调用接口，最少请提供：

- AppKey / Client ID。
- AppSecret / Client Secret（通过密钥渠道）。
- 作为操作人的钉钉成员：姓名、手机号或 userId，最好再提供所在部门。
- 要同步的知识库：名称、钉钉访问链接或截图。
- 要同步的钉盘空间：名称、钉钉访问链接或截图。
- 已开通权限截图，或在填写表中勾选“是/否/不适用”。

1. 在「应用开发」中打开目标企业内部应用。
2. 进入「凭证与基础信息」或「基础信息」页面。

- AppKey 可以明文发给配置人。
- AppSecret 必须按密钥处理。
- 不要把含 AppSecret 的后台截图发到群里。

## 4. 获取操作人 UnionID

WeKnora 同步钉盘和知识库时，需要一个「操作人 UnionID」。这个成员相当于同步账号：系统会以这个成员的权限读取他能访问的钉钉内容。

重要提醒：

- UnionID 通常不在钉钉应用页面直接展示。
- 不要用企业 `CorpID`、手机号、姓名直接替代 UnionID。
- `UserID` 和 `UnionID` 也不是同一个字段；很多后台页面能看到的是 UserID，但 WeKnora 当前同步需要的是 UnionID。

### 4.1 推荐方式：通过接口查询 UnionID

第一步，获取企业内部应用 access_token。

```bash
curl -X POST "https://api.dingtalk.com/v1.0/oauth2/accessToken" \
  -H "Content-Type: application/json" \
  -d '{
    "appKey": "替换为 Client ID / AppKey",
    "appSecret": "替换为 Client Secret / AppSecret"
  }'
```

返回中复制 `accessToken`。钉钉官方说明中，企业内部应用调用服务端 API 需要先通过 AppKey/AppSecret 获取 accessToken。

第二步，确认操作人的 `userId`。管理员通常可以通过以下方式获得：

- 通讯录成员详情、通讯录导出表。
- 根据手机号查询用户接口。
- 获取部门用户 userId 列表接口。

第三步，用 userId 查询用户详情，复制返回里的 `unionid` / `unionId`。

```bash
curl -X POST "https://oapi.dingtalk.com/topapi/v2/user/get?access_token=替换为accessToken" \
  -H "Content-Type: application/json" \
  -d '{
    "userid": "替换为操作人的userId",
    "language": "zh_CN"
  }'
```

返回结果里通常会包含：

```json
{
  "result": {
    "userid": "员工userId",
    "unionid": "这里就是要填写的操作人UnionID"
  }
}
```

如果你使用的是钉钉新版接口调试页，请直接打开「查询用户详情」接口，填入 `accessToken` 和 `userId`，在响应体里找 `unionid`。

### 4.2 管理员不会调接口时，请提供这些信息

如果管理员无法操作接口，把以下信息填到参数表里，我们来查：

- 操作人姓名。
- 操作人手机号。
- 操作人 userId（如果通讯录能看到）。
- 操作人所在部门。
- 确认该成员能打开目标知识库或钉盘：是 / 否。
- 确认该成员在应用可见范围内：是 / 否。

### 4.3 操作建议

1. 优先使用一个专门的钉钉成员作为同步账号，例如「WeKnora同步账号」。
2. 确认该成员能打开目标钉盘空间或目标知识库。
3. 如果后台只显示 `UserID` 而不显示 `UnionID`，按 4.1 通过接口查询，或按 4.2 提供信息让我们查询。

## 5. 开通接口权限

进入目标应用后，打开「权限管理」或「接口权限」页面，按同步类型开通权限。

下面这份清单按当前 WeKnora 代码核对过：数据源同步代码位于 `internal/datasource/connector/dingtalk`，钉钉 IM 机器人代码位于 `internal/im/dingtalk`。

### 5.1 必开：基础令牌

| 能力 | 当前代码调用 | 权限/后台动作 |
|---|---|---|
| 获取 Access Token | `POST /v1.0/oauth2/accessToken`，失败时兼容旧接口 `/gettoken` | 无单独业务权限，但 AppKey / AppSecret 必须正确，应用必须可用 |

### 5.2 钉盘/云盘同步

建议搜索并开通以下权限：

| 权限标识 | 当前代码调用 | 用途 |
|---|---|---|
| `Drive.Space.Read` | `GET /v1.0/drive/spaces` | 读取操作人可见的企业钉盘空间列表 |
| `Storage.File.Read` | `GET /v1.0/storage/spaces/{spaceId}/dentries`、`GET /v1.0/storage/spaces/{spaceId}/dentries/{dentryId}`、`POST /v1.0/storage/spaces/{spaceId}/dentries/{dentryId}/downloadInfos/query` | 读取钉盘目录、文件元数据和下载信息 |

当前代码说明：

- 钉盘原生在线文档会读取正文。
- 普通上传附件当前版本会识别并跳过；如后续要让机器人下载和处理附件，仍需要保留 `Storage.File.Read`。

### 5.3 知识库同步

建议搜索并开通以下权限：

| 权限标识 | 当前代码调用 | 用途 |
|---|---|---|
| `Wiki.Workspace.Read` | `GET /v2.0/wiki/workspaces` | 获取操作人可访问的知识库列表 |
| `Wiki.Node.Read` | `GET /v2.0/wiki/nodes`、`GET /v2.0/wiki/nodes/{nodeId}` | 获取知识库目录、节点和节点详情 |
| `Storage.File.Read` | `GET /v1.0/doc/suites/documents/{docKey}/blocks` | 读取知识库在线文档块正文 |
| `Document.Workbook.Read` | `GET /v1.0/doc/workbooks/{workbookId}/sheets`、`GET /v1.0/doc/workbooks/{workbookId}/sheets/{sheetId}/ranges/{rangeAddress}` | 读取知识库里的钉钉在线表格、工作表和单元格内容 |

当前代码说明：

- 知识库在线文档会同步为 Markdown。
- 知识库在线表格会读取工作表和单元格内容，并同步为 Markdown 表格。
- 白板、脑图、表单、演示、PDF 阅读内容等暂不支持同步，代码会记录跳过原因。

### 5.4 必开：把钉钉应用变成可对话机器人

如果要支持用户在钉钉里和 WeKnora 应用机器人聊天，请完成以下后台动作：

1. 在应用详情页进入「添加应用能力」。
2. 添加「机器人」能力。
3. 进入「机器人」配置页。
4. 消息接收模式优先选择「Stream 模式」。如果使用 Webhook，则选择「HTTP 模式」并填写 WeKnora 生成的回调地址。
5. 创建版本并发布应用，确保应用可见范围包含要使用机器人的成员或群。

同时开通以下权限：

| 权限标识 | 当前代码调用 | 用途 |
|---|---|---|
| `qyapi_robot_sendmsg` | `POST /v1.0/robot/groupMessages/send`、`POST /v1.0/robot/oToMessages/batchSend` | 让应用机器人给群聊或人与机器人单聊发送消息 |

机器人配置参数：

| 参数 | 当前代码字段 | 说明 |
|---|---|---|
| Client ID / AppKey | `client_id` | 同步数据源的 AppKey 可以复用 |
| Client Secret / AppSecret | `client_secret` | 同步数据源的 AppSecret 可以复用，但仍按密钥管理 |
| Card Template ID | `card_template_id` | 可选，启用 AI 卡片流式回复 |

### 5.5 可选但建议：AI 卡片流式回复

如果要让机器人回复呈现打字机式 AI 卡片，请在钉钉卡片平台创建并发布 AI 卡片模板，然后开通：

| 权限标识 | 当前代码调用 | 用途 |
|---|---|---|
| `Card.Instance.Write` | `POST /v1.0/card/instances/createAndDeliver` | 创建并投放 AI 卡片 |
| `Card.Streaming.Write` | `PUT /v1.0/card/streaming` | 流式更新 AI 卡片内容 |

如果不启用 AI 卡片，机器人仍可通过普通 Markdown 消息回复。

### 5.6 为“机器人操作知识库/在线文档”预开通的写权限

你们当前目标是让 AI 应用机器人不只是回答问题，还可以帮忙读写各项在线文档、下载内容，并直接操作钉钉知识库。为避免后续上线写入能力时再次找管理员补权限，建议一并申请以下权限。

| 权限标识 | 规划用途 | 备注 |
|---|---|---|
| `Storage.File.Write` | 写入、追加或修改钉钉在线文档块内容；管理文件相关写操作 | 钉钉文档块插入/追加等接口要求企业存储文件写权限 |
| `Document.Workbook.Write` | 修改在线表格工作表、单元格、追加行等 | 当前代码只读表格；机器人写表格时需要 |
| `Wiki.Workspace.Write` | 新建或管理知识库空间 | 如只在已有知识库内读写文档，可能不是第一阶段必需 |
| 知识库文档写权限 / `Document.WorkspaceDocument.Write` | 创建或维护知识库里的文档内容 | 钉钉后台名称可能随页面调整，请以权限管理搜索结果为准 |

写权限风险更高，建议配合以下限制：

- 使用专门的同步/机器人钉钉成员作为操作人。
- 只把应用可见范围给到需要使用的人或部门。
- 只让操作人加入允许 AI 操作的目标知识库或钉盘空间。
- 首期可以先开读权限和机器人消息权限；确认流程后再开写权限。

如果调用接口时报错里出现 `requiredScopes`，请把报错中的权限标识补充开通。

## 7. 获取知识库 WorkspaceID（仅知识库同步需要）

优先方式：让 WeKnora 使用 AppKey、AppSecret、UnionID 自动列出可访问知识库，然后在界面里选择。

`workspaceId` 一般不在普通知识库页面直接展示。钉钉官方说明里，知识库 ID 要通过「获取知识库列表」接口返回的 `workspaceId` 字段获取。

### 7.1 推荐方式：通过接口查询 workspaceId

前提：

- 已按第 4 节拿到操作人 `unionId`。
- 已拿到企业内部应用 `accessToken`。
- 已开通 `Wiki.Workspace.Read`。
- 操作人能访问目标知识库。

调用知识库列表接口：

```bash
curl -X GET "https://api.dingtalk.com/v2.0/wiki/workspaces?maxResults=30&orderBy=VIEW_TIME_DESC&withPermissionRole=true&operatorId=替换为操作人UnionID" \
  -H "x-acs-dingtalk-access-token: 替换为accessToken" \
  -H "Content-Type: application/json"
```

返回结果里找目标知识库名称，对应字段通常包括：

```json
{
  "workspaces": [
    {
      "workspaceId": "这里就是知识库ID",
      "rootNodeId": "知识库根节点ID",
      "name": "知识库名称",
      "url": "知识库链接",
      "permissionRole": "查询人权限"
    }
  ],
  "nextToken": "如果不为空，表示还有下一页"
}
```

如果 `nextToken` 不为空，需要带上 `nextToken` 再查下一页，直到找到目标知识库。

交付时写成：

```text
知识库 WorkspaceID：xxxxxxxx
```

或：

```text
wiki:xxxxxxxx
```

### 7.2 管理员不会调接口时，请提供这些信息

如果管理员无法操作接口，把以下信息填到参数表里，我们来查：

- 目标知识库名称。
- 目标知识库钉钉访问链接。
- 目标知识库截图，截图里尽量包含名称和路径。
- 操作人姓名、手机号或 userId。
- 确认操作人能打开该知识库：是 / 否。
- 如果知识库很多，请说明大概所属部门、团队或知识小组。

### 7.3 注意事项

- 不要填写浏览器地址代替 `workspaceId`。

- 如果接口返回 `permissionRole` 是 `NONE`，说明操作人没有权限访问该知识库，需要先给操作人授权。

## 8. 获取钉盘 SpaceID（仅钉盘同步需要）

优先方式：让 WeKnora 使用 AppKey、AppSecret、UnionID 自动列出可访问钉盘空间，然后在界面里选择。

`spaceId` 一般也不在普通钉盘页面明显展示。钉钉官方说明里，钉盘空间 ID 要通过「获取空间列表」接口返回的 `spaceId` 字段获取。

### 8.1 推荐方式：通过接口查询 spaceId

前提：

- 已按第 4 节拿到操作人 `unionId`。
- 已拿到企业内部应用 `accessToken`。
- 已开通 `Drive.Space.Read`。
- 操作人能访问目标钉盘空间。

调用空间列表接口：

```bash
curl -X GET "https://api.dingtalk.com/v1.0/drive/spaces?unionId=替换为操作人UnionID&spaceType=org&maxResults=50" \
  -H "x-acs-dingtalk-access-token: 替换为accessToken" \
  -H "Content-Type: application/json"
```

返回结果里找目标钉盘空间名称，对应字段通常包括：

```json
{
  "spaces": [
    {
      "spaceId": "这里就是钉盘空间ID",
      "spaceName": "空间名称",
      "spaceType": "org"
    }
  ],
  "nextToken": "如果不为空，表示还有下一页"
}
```

如果 `nextToken` 不为空，需要带上 `nextToken` 再查下一页。

交付时写成：

```text
钉盘 SpaceID：xxxxxxxx
```

或：

```text
space:xxxxxxxx
```

### 8.2 管理员不会调接口时，请提供这些信息

如果管理员无法操作接口，把以下信息填到参数表里，我们来查：

- 目标钉盘空间名称。
- 目标钉盘文件夹或空间访问链接。
- 目标钉盘截图，截图里尽量包含空间名称和路径。
- 操作人姓名、手机号或 userId。
- 确认操作人能打开该钉盘空间：是 / 否。
- 如果只同步某个文件夹，请说明文件夹名称和层级路径。

### 8.3 注意事项

- 不要填写浏览器地址代替 `spaceId`。
- 不要把知识库 `workspaceId` 填到钉盘里。
- 如果能列出空间但列不出文件夹，请继续确认 `Storage.File.Read` 是否开通，以及操作人是否有目标目录权限。

## 9. 最终交付前自检

请管理员在交付前确认：

- 已提供 AppKey / Client ID。
- 已通过安全渠道提供 AppSecret / Client Secret。
- 已提供操作人 UnionID。
- 已说明同步类型是「知识库」还是「钉盘」。
- 已开通对应的 Drive / Storage / Wiki / Document 权限。
- 如果要使用钉钉对话机器人，已添加「机器人」应用能力并开通 `qyapi_robot_sendmsg`。
- 如果要使用 AI 卡片流式回复，已创建并发布卡片模板，已开通 `Card.Instance.Write` 和 `Card.Streaming.Write`。
- 如果要让机器人后续写入或修改在线文档/表格/知识库，已评估并开通 `Storage.File.Write`、`Document.Workbook.Write`、`Wiki.Workspace.Write` 等写权限。
- 操作人在应用可见范围内。
- 操作人能在钉钉客户端打开目标知识库或钉盘。
- 如果手动提供 ID，知识库使用 `workspaceId`，钉盘使用 `spaceId`。

## 10. 常见问题

### 10.1 AppKey 在后台找不到，只看到 Client ID

可以使用 Client ID。钉钉新版后台可能把 AppKey 显示为 `Client ID（原 AppKey）`。

### 10.2 AppSecret 在后台找不到，只看到 Client Secret

可以使用 Client Secret。钉钉新版后台可能把 AppSecret 显示为 `Client Secret（原 AppSecret）`。

### 10.3 UnionID、UserID、CorpID 是同一个东西吗

不是。

- UnionID：当前同步需要的操作人标识。
- UserID：企业通讯录里的成员 ID，部分产品或接口会用，但当前同步配置不要直接拿它替代 UnionID。
- CorpID：企业标识，当前 WeKnora 钉钉同步通常不是必填项。

### 10.4 为什么能拿到 AppKey 和 Secret，还是同步不到知识库

常见原因：

- 没有开通 Wiki 相关接口权限。
- 操作人不能访问目标知识库。
- 应用可见范围没有包含操作人。
- 手动 ID 填错，把钉盘 spaceId 和知识库 workspaceId 混用了。

### 10.5 为什么能同步钉盘，不能同步知识库

钉盘和知识库是两套不同 API。钉盘通常使用 `spaceId`，知识库使用 `workspaceId`。已开通 `Drive.Space.Read` / `Storage.File.Read` 不代表已经开通知识库权限。

### 10.6 为什么能同步文档，但机器人不能聊天

同步文档只需要数据源读权限；机器人聊天还需要在应用能力中添加「机器人」，配置 Stream 或 HTTP 消息接收模式，并开通 `qyapi_robot_sendmsg`。

### 10.7 为什么普通消息能回复，但没有 AI 卡片流式效果

普通消息只需要机器人发送消息权限。AI 卡片流式效果还需要创建卡片模板，并开通 `Card.Instance.Write` 和 `Card.Streaming.Write`。

### 10.8 机器人写文档权限现在一定要开吗

如果只做同步读取和聊天问答，可以先不开写权限。如果目标是让 AI 机器人直接改写钉钉在线文档、在线表格或知识库，建议按 5.6 预先申请写权限，并限制操作人和应用可见范围。
